    #T02 · Dodge

    ---
    AI 사용: STEP 1 · 대화형으로 요구하기
    한 일: 레벨 디자인, 점진적 기능 추가, 상세 요구
    링크: aleph-project-dodge.vercel.app ↗
    ---

    30초 동안 탄막을 피하는 생존 게임입니다. 30초에 끝나는 간단한 미니게임이라는 주제에서 예전에 했던 피하기 게임을 떠올려 만들었습니다.

    ##AI로 넣은 기능과 이유

    • 시간대별로 다른 공격피하기만 하면 단조로워서, 시간에 따라 직선, 곡선, 유도 공격이 나오게 했습니다. 30초에 가까워질수록 어려워지고 긴장감이 들게 하려는 레벨 디자인입니다.
    • 난이도 세 단계난이도에 맞춰 장애물의 개수와 속도가 늘어나게 했습니다. 처음 나오는 장애물은 쉬움 3개, 보통 5개, 어려움 8개입니다.
    • 상한 없는 도전 모드난이도를 나누고 보니 사람마다 실력 차이가 크다는 것을 알게 되어, 단계에 상한을 두지 않았습니다. 쉬운 모드는 아주 쉽게 했습니다.
    • 캐릭터 직접 그리기기본 캐릭터만 있으면 심심할 것 같아서, 도화지에 직접 그려 캐릭터를 만들 수 있게 했습니다.
    • 최근 기록상한 없는 모드가 생기자 경쟁심이 있는 사람은 자기 위치를 보고 싶어 할 것 같아서 최근 기록을 볼 수 있게 했습니다.
    • 접을 수 있는 영역기능을 더하자 화면이 길어져 스크롤이 생겨서, 튜토리얼과 캐릭터 만들기처럼 항상 볼 필요 없는 것을 접어 공간을 줄였습니다.

    ##연결

    기능 하나가 다음 문제를 만들었고, 그 문제를 다음 기능으로 풀었습니다. 난이도를 나누자 실력 차이가 보였고, 상한 없는 모드를 만들자 기록이 필요해졌고, 기능이 늘자 화면이 길어졌습니다.

    ##배운 것

    컨셉만 잡고 기본 틀을 요구한 뒤 간단한 기능을 하나씩 더하며, 자세히 요구하는 법을 익혔습니다.

    #T04 · The Day Before

    ---
    AI 사용: STEP 2 · 프로젝트 단위로 대화하기
    한 일: 참고 디자인 지정, 여러 안 중 선택, 편의 기능 추가, 자동 기록
    기록: GitHub Actions 자동 기록 54일 중 52일
    링크: 배포 사이트 ↗ · GitHub ↗
    ---

    어제 하루 동안 생성된 공개 GitHub 저장소 수를 매일 기록하는 대시보드입니다. 외부 API가 실패해도 가짜 값을 채우지 않고 지연 상태를 보여 줍니다.

    ##AI로 넣은 기능과 이유

    • 편의 기능 세 가지잔디 모양의 기록 표시, 추이 그래프, 중앙의 큰 숫자 갱신을 더했습니다. 요구받은 기능 밖에서 편의성을 높이려고 시각적으로, 기능적으로 더한 것입니다.

    ##상황

    처음에는 AI가 추천한 디자인을 그대로 따랐는데 마음에 들지 않는 부분이 있었습니다.

    ##해결

    가능한 제안을 여러 개 나열해 달라고 요청하고 그중에서 직접 고르는 방식으로 바꿨습니다. 참고할 디자인과 원하는 모습을 지정하고 세부 디자인까지 요구했습니다.

    ##확인

    GitHub Actions의 자동 기록이 54일 중 52일 이어졌고, 제출 뒤에도 표의 가독성과 그래프 라벨 겹침을 고쳤습니다.

    #T07 · PinPoint 재설계

    ---
    기간: 2026.09.03 – 09.06 (커밋 37개)
    AI 사용: STEP 3·4 · 폴더 안 명세, 외부 도구(MCP) 연결
    한 일: 로그인 구현, 전체 재설계, Document PiP 구현
    링크: aleph-pinpoint.vercel.app ↗
    ---

    전체 배치를 다시 설계했습니다. 픽셀 테마는 부분 수정 대신 기초부터 다시 만들고, 작업 원칙 · 구조 · 검증 기준을 문서로 정리했습니다.

    ##상황

    코르크보드와 픽셀에 이어 Win95 테마까지 구현했지만, 기능을 고칠 때마다 무료 이미지의 저작권을 확인하는 일이 작업량을 크게 늘렸습니다.

    ##해결

    팀원들에게 보였을 때 칭찬은 들었지만 관심이 다른 테마에 몰려서, 구현 사흘 만에 모든 페이지에서 제거했습니다. 달성 이벤트 디자인은 여러 안을 나란히 만들어 비교한 뒤 정했고, 핀 모드는 복잡하게 만들었다가 줄이고 다시 조정했습니다.

    ##확인

    로그인 뒤 다른 사람의 자료가 열리지 않는 것을 확인한 기록과, 막지 못한 것(무차별 대입 방어 등)의 목록을 제출 문서에 남겼습니다.

    #T10 · 미로형 3D 공간에서 고정 청각 랜드마크의 개수가 길찾기에 미치는 영향

    ---
    날짜: 2026.10.01
    한 일: 가설 설정, 브라우저 3D 시뮬레이터 직접 제작, 사전 분석 계획
    자료: 참가자 5명, 시행 15회
    링크: 논문 전문 · 소스와 원자료 GitHub ↗
    ---

    서로 다른 음색의 소리를 0개, 2개, 3개 둔 미로를 브라우저 3D 시뮬레이터로 직접 만들었습니다. 참가자 5명의 시행 15회를 수집해 소요 시간, 경로 효율성, 막다른 길 진입 횟수를 비교했습니다.

    ##상황

    설계를 바꾸며 실험해서 참가자 5명의 설계 버전이 서로 달라 시간을 그대로 합칠 수 없었습니다. 소리가 들리는 최대 거리도 처음에는 최단경로 위의 거리만 보고 60유닛으로 잘못 정했습니다.

    ##해결

    같은 사람의 소리 없는 시행과 비교한 비율로 분석했고, 최대 거리를 90유닛으로 고쳤습니다. 분석 계획은 데이터를 보기 전에 정했고, AI가 한 일과 직접 판단한 일을 문서에 나누어 적었습니다.

    ##결과

    소리 3개 조건이 소리 없는 조건보다 빨랐던 참가자는 5명 중 4명이었습니다(시행 순서를 통제한 3명 중에서는 2명). 표본이 작아 가설의 지지와 기각은 판단하지 않고 탐색적 경향으로만 적었습니다.
